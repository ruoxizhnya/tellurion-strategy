# 0003 · 存储/缓存/作业落地与产物可复现性

- **状态**：已裁决（2026-10-24，QT-41/G4 施工）
- **场景**：首批实装只有 `Memory` Store、进程内 build job、零缓存，且 TinyGo 产物未接过真工具链。
  实测三件事逼出了决策：
  1. `CHAR(64)` 读回会补空格，内容寻址比较会被破坏（PG 实现必须 `trim`）；
  2. `promote` 的「artifact 状态 + definition 生效指针」分两步写，第二步失败会留下无法自愈的半截状态；
  3. TinyGo 0.34.0 默认把源文件绝对路径写进 DWARF，Runner 的随机临时目录会让同源码两次编译得到
     **不同 `artifact_hash`**（实测 17711 字节，两个 hash；加 `-no-debug` 后 270 字节、逐字节一致）。
- **决策**：
  1. PG `Store` 是生产实现；`cmd/assetservice` 在 DSN 非空时先 `OpenPG` → `Migrate`（幂等 DDL）再监听。
     `Memory` 只用于单仓测试 / 本地演示，启动日志明确标注非持久化。
  2. `promote` / `deprecate` 收进 Store 的**单事务**方法；Service 不再分两步写。
  3. artifact 字节走两级缓存：L1 内存 LRU + L2 本地磁盘内容寻址（`<dir>/<hash[:2]>/<hash>`），
     只按容量驱逐；L2 读出必须重算 sha256，与文件名不符即删并 miss。**artifact 永不 TTL。**
  4. `latest` 解析结果按 strategy_id 缓存 TTL **300s**；`promote` / `deprecate` 成功后同进程主动失效。
  5. build job 落 `strategy.strategy_build_jobs`，`202` 返回的 `job_id` 用
     `GET /api/strategies/{id}/builds/{job_id}` 查询；路径 id 必须与作业归属一致。
  6. 14 个内置策略在启动时同步登记为 `carrier=builtin`（定义存在、无 artifact）；同名不同形状 fail-loud，不覆盖。
  7. `carrier=so` 的 `Verify` 增加导出符号表校验：entry 必须是 `.dynsym`（无则 `.symtab`）里已定义的
     GLOBAL/WEAK 函数（或 NOTYPE）；不是 ELF / 非 ET_DYN 一律拒。
  8. `compile.Config` 对 `name=tinygo` 强制要求精确参数 `-no-debug`：这是让产物与临时路径无关、
     `artifact_hash` 可离线复现的前提。工具链二进制 sha256 由 `internal/compile/toolchains.lock` 锁定。
- **理由**：
  - 不落 PG 就无法满足「服务停机后按 hash 复现」与多实例；内存实现不能冒充持久化。
  - 事务边界放在 Store：内存实现用一把锁，PG 用 BEGIN/COMMIT，Service 不必知道两种实现的差异。
  - 缓存分层按对象语义拆开：内容寻址对象用「容量」驱逐即可，加 TTL 只会破坏离线复现；可变引用（latest）才需要 TTL。
  - job 不落库则「202 之后进程重启，job_id 永久 404」，查询端点没有意义。
  - 内置策略登记只做定义、不迁源码：G 裁决已明确「保留 init + 同步登记」，避免启动期网络依赖与全量迁移。
  - so 的导出符号是挂载时的硬前提；只比 hash 等于把失败推迟到运行时。
  - 否掉的选项：给 `Runner` 固定临时目录（并发下冲突、且跨机器路径仍不同）；用 `-trimpath`（TinyGo 0.34 无此开关）；
    给 artifact 缓存加 TTL（与「artifact 永不失效」直接冲突）；把 job 放 Redis（新增基础设施，F 裁决禁止）。
- **代价 / 后果**：
  - 改了编译参数（含去掉 `-no-debug`）必须视为换构建配方：更新 toolchain 标识与锁文件，否则同
    `(version_hash, toolchain)` 会与已登记字节冲突（fail-closed）。
  - latest 的跨进程一致性窗口最长 300s（F 裁决的显式取舍）。
  - 磁盘缓存与业务库同机；容量上限是部署参数，超限只丢副本。
  - 机械检查：`TestPG_StatusMachineAndTransactionalPromote`（故意让第二步失败，断言回滚）、
    `TestService_LatestCacheTTLAndPromoteInvalidation`、`TestPG_BuildJobsPersistAcrossInstances`、
    `TestConfig_TinyGoRequiresNoDebug`、`TestPinnedTinyGoArtifactIsOfflineVerifiable`。
- **替代关系**：无（补充 0002 的存储形态；不改变 artifact 主键与生效字节的裁决）。
