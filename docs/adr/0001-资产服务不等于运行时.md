# 0001 · 资产服务不等于运行时

- **状态**：已裁决（来源：ADR-D6 / ADR-D13 / ADR-D14 / QT-41）
- **场景**："把策略拆出去"这句话里混着两件事：策略**资产**（定义/版本/artifact/解析）和策略**运行时**（逐 bar 执行）。前者天然适合出仓（低频、可缓存、字节码可控）；后者一旦出仓，每个 bar 都要一次远程调用，回测直接慢几个数量级，还会把"沙箱"变成"网络边界"。
- **决策**：① 本仓只做资产与解析（写侧 7 端点 + 读侧 2 端点）；② 执行留在 core 的 WASM host，进程内；③ 引擎按 `artifact_hash` 缓存，永不失效；④ 解析失败 fail-closed，不回退内置策略。
- **理由**：资产是"低频、可缓存、可离线复现"的；运行时是"高频、有状态、延迟敏感"的。按这个差异切，服务化才有收益；不按它切，就是把回测变成分布式系统。
- **代价 / 后果**：① 引擎侧要维护 artifact 缓存与五道加载校验；② 编译工具链（TinyGo 等）成为构建依赖；③ 同一个策略的"定义在服务、执行在 core"，调试时要跨两处看。
- **替代关系**：无（本仓首条）
