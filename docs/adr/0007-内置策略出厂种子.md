# 0007 · 内置策略的出厂种子（F6 根因修复）

- **状态**：已裁决（2026-11-13）
- **关联**：[ADR-0006](0006-builtin无artifact激活路径.md)（builtin 的版本级激活路径）、`tellurion` 仓
  `docs/COMPREHENSIVE-TEST-PLAN-2026-11-13.md` §7.3 F6。

## 背景与根因

综合测试（2026-11-13，隔离栈 `tellurion-next`）在 W4.5「策略解析链路」观察到：

```
GET /api/strategies/momentum/versions          → 200 []
GET /api/strategies/momentum/resolve?ref=latest → 404 no_active_version
GET /api/strategies/none/versions               → 404 strategy_not_found
```

判据链把根因钉死在**出厂登记只做了一半**，不是 resolve 语义：

1. `momentum` 的 `/versions` 是 `200 []`（而不是 404）⇒ 定义行**存在**，`RegisterBuiltins` 确实跑过；
2. 未知策略 `none` 才是 404 ⇒ 定义查询本身正常，不是「内置策略从未登记」；
3. `resolve?ref=latest` 的判据是 `definition.active_version_hash != ""`（ADR-0006 §2）⇒
   **没有 active 版本**才是 404 的直接原因；
4. 旧 `RegisterBuiltins` 只调 `CreateDefinition`：不登记 `strategy_versions`、从不写
   `active_version_hash`。ADR-0006 开放的 validate / promote 路径只能由人工事后调用，
   出厂的内置策略没有任何人替它走这一步。

所以是「seed 了定义，但没 seed 版本，也没置 active」，属于**空库不自洽**：二进制内有 14 个
内置实现（启动日志 `builtin strategies registered count=14`），库里却没有可解析的资产状态。
W4.5 因此只能记 BLOCKED(前置缺失)。

## 决策

按 risk 仓 `internal/rule/seed.go` 的出厂种子模式，给内置策略补齐**可解析的出厂状态**，
而不是在 resolve 里对「没有」做缺省兜底：

1. **每条内置策略在一个事务里完成三步**：建定义 → 登记出厂版本（`carrier=builtin`、
   `source=<name>@builtin (in-binary implementation)`、hash 走 contracts 唯一编码器）→
   置 `active_version_hash`（`active_artifact_hash` 保持空，ADR-0006 契约）。
   PG 用单事务，Memory 用单锁；中途失败整条回滚，不留「有定义无版本」的半套。
2. **审计 actor 固定 `factory-seed`**：`strategy.strategy_promotions` 追加一行
   （`actor=factory-seed`、`outcome=promoted`、`artifact_hash=""`），与人工 promote
   （`X-Actor`）可区分。审计写失败 ⇒ 启动失败，不悄悄丢审计。
3. **幂等 / 不覆盖人工改动**：已存在且（a）有 active 版本，或（b）已登记过任何版本 ⇒
   整条跳过，一个字节都不写。人工写源 / 人工 promote 永远赢过出厂种子。
4. **补齐旧库**：定义存在但「从未有版本、从未有 active」是 F6 现场的形态（旧版本只建定义），
   种子补齐版本与 active；这不是 update 既有内容，而是完成中断的出厂登记。
5. **同名不同形状仍 fail-loud**：同 id 已是 wasm/dsl、或 scope/entry 漂移 ⇒ 启动失败
   （`ErrArtifactConflict`），绝不覆盖别人的定义与命名空间。
6. **resolve 不做兜底**：不新增「找不到 active 就用内置同名策略」的分支；内置策略能解析
   的唯一原因是**库里真的有出厂 active 版本**。ADR-0006 的消费判据（`status=promoted` +
   `carrier` 明确）不变。

## 否决的替代方案

1. **resolve 时对 builtin 回落到「策略名 = 内置实现」**：把「没有」当「有」，与
   `docs/dataflow.md`「无 active 版本 = fail-closed，禁止静默用内置策略」直接冲突；
   且 `active_version_hash` 仍为空，审计里没有「哪个版本生效」。
2. **只 seed 定义、继续要求人工 validate → promote**：F6 现场就是这条路径没人走；
   空库新部署仍然不可用，等于把缺陷留在出厂状态。
3. **给 builtin 造占位 artifact 来满足旧状态机**：ADR-0006 已否决（污染内容寻址）。
4. **无条件对已存在定义补 active**：会覆盖人工 promote 的选择（人工把某个版本标为
   active 后，重启又被改回出厂版本），违反「绝不 update」。

## 代价 / 后果

1. **每个内置策略多一行版本**（14 行 `strategy_versions`）与一条审计行；版本 hash 稳定，
   重启不会新增行。
2. **`GET /versions` 不再是空数组**：内置策略的出厂版本可见；其 `status` 仍由 artifact 行
   派生为 `source`（ADR-0006 后果 2 不变），生效版本以 `resolve` / `active_version_hash` 为准。
3. **升级行为**：旧库（只有定义）在下次启动时补齐；有人动过的内置策略保持原状。若运维
   手工删除了某内置策略的版本行与 active 指针，重启会把它补回（与 risk 的
   「被删除的出厂规则下次启动补回」同口径）。
4. **机械检查**：
   - `internal/asset/builtin_test.go`：`TestService_RegisterBuiltinsIsIdempotent`（种子含
     version + active、14 条均可 resolve、重启 0 写入）、
     `TestService_RegisterBuiltinsCompletesLegacyDefinition`（旧库补齐）、
     `TestService_RegisterBuiltinsDoesNotOverwriteHumanPromotion`（人工 promote 赢）、
     `TestService_RegisterBuiltinsRecordsFactoryAudit`（审计 actor / 不重复）、
     `TestPG_RegisterBuiltins` / `TestPG_RegisterBuiltinsCompletesLegacyDefinition`（真 PG）；
   - `internal/httpapi/builtin_lifecycle_test.go`：
     `TestBuiltinResolveIsAvailableAfterFactorySeed`（`momentum/resolve?ref=latest` 200）。
